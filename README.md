# Solarion

基于 Bevy 0.20 的 3D 横版剑与魔法小队战斗原型。当前版本是一个可运行的垂直切片：四名角色自动推进、自动攻击/自动释放技能，连续击败三波敌人并在第三波迎战 Boss。

## 运行

```bash
cargo run
```

首次编译 Bevy 需要较长时间。调试构建已经开启依赖优化（见 `Cargo.toml`），但仍建议在实际试玩时使用：

```bash
cargo run --release
```

结算界面按 `R` 重新开始。

## 数据文件（RON）

角色、技能、敌人/波次和装备参数都在启动时从 `assets/data/` 读取，修改后**重启游戏**即可生效，不需要重新编译：

```
assets/
├── data/
│   ├── heroes.ron      # 角色、被动、3 个主动技能、基础属性、技能图标与模型路径
│   ├── enemies.ron     # 波次列表与敌人模板（count 表示一波生成数量）
│   └── equipment.ron   # 品级主属性倍率、各部位主属性、副词条范围、初始装备品级表
├── icons/skills/       # 64×64 技能图标（CC0，来源见该目录 README）
├── models/heroes/      # 角色 glTF 模型与动画（CC0，来源见 CREDITS.md）
├── textures/floor/     # 可平铺地板纹理（CC0，来源见 CREDITS.md）
└── shaders/
    └── skill_cooldown.wesl   # 技能扇形冷却遮罩的 UI 材质着色器
```

- 技能蓝耗必须是 `100` 的正整数倍（HUD 会用圆点数量表示）。
- `icon` 使用相对于 `assets/` 的路径，例如 `icons/skills/arcane-missile.png`；留空则不显示图标。
- 角色的 `model` 使用相对于 `assets/` 的 glTF 路径（如 `models/heroes/xbot_animated.glb`）；留空则回退为胶囊体占位。
- 角色的 `attack_range` 是普通攻击射程；技能的 `range` 是进攻技能射程，必须大于 0。己方 Buff/治疗写 `0.0`，表示无射程限制。
- 冷却遮罩通过 `assets/shaders/skill_cooldown.wesl` 绘制，进度按顺时针方向消退。
- `enemies.ron` 中每个敌人只需定义一次，用 `count` 控制这一波的生成数量。
- 装备词条内部用小数表示百分比：`0.05` 即 `5%`。
- 如果 RON 语法或字段校验失败，游戏会直接退出并打印具体文件与错误信息。
- 资源根目录会在启动时自动定位（支持 `cargo run` 和直接运行 `target/debug/solarion-rs.exe`）。

## 当前实现

- **3D 横版关卡**：正交相机固定在行进方向的侧面，视线方向约为 `(0, -1, -1)`（水平侧视 + 45° 俯视），镜头只沿 X 轴跟随队伍，不重新调整朝向；水平地面使用网格纹理，角色按 Z 轴错开。三波敌人（第三波为 Boss），清空当前波次后继续前进。
- **角色模型与动画**：使用 Quaternius Sword and Shield Pack 的 X Bot glTF，播放 idle / run / attack / casting 动画；模型根节点由数据中的 `model` 字段配置。
- **四名角色**：坦克、输出、辅助、治疗，各有一个被动和三个主动技能。
- **自动战斗**：普通攻击自动选择射程内最近的敌人；技能按优先级、法力、冷却、射程和智能条件（低血量治疗、Buff 未生效等）自动施放。近战单位必须等敌人进入射程后才会出手；针对己方的 Buff/治疗没有射程限制。
- **法力系统**：上限 500，底部队列显示为 5 格，满格亮色、未满格按实际进度暗色填充；每秒回复，普通攻击额外回复；技能消耗均为 100 的整数倍。
- **伤害模型**：物理/魔法两种攻击类型，防御减伤 `def / (K + def)`，`K` 仅由攻击方等级决定；暴击基伤 200%，支持暴击率/暴伤/穿透/闪避/攻速。
- **浮动战斗信息**：伤害与治疗数值锚定在目标头顶（按目标缩放计算头高），上浮并淡出；物理伤害红字、魔法伤害蓝字、治疗绿字，暴击使用同色系更亮的颜色和更大的字号。多段伤害只在屏幕空间纵向叠放，不会偏移到其他角色头顶。
- **属性结算**：基础属性 + 装备主属性 → 百分比副属性 → 技能/Buff 增幅；暴击、攻速、闪避、穿透直接相加。
- **装备框架**：六个部位、五档品级、主属性与随机副属性池；白/绿/蓝/紫/橙分别对应 0–4 条副属性，同件装备副属性不重复。开局会为每名角色生成一套随机初始装备。
- **成长与奖励**：通关结算经验并升级；Boss 波清空后掉落经验药水，药水库存会累积。
- **战斗统计**：输出、治疗、承伤三个排行榜，位于左上角，点击 Tab 切换。
- **HUD 与结算**：横贯屏幕底部的四角色队列（肖像、生命条、5 格法力、3 个主动技能按钮）、波次信息、Boss 波顶部血条、胜利/失败遮罩。技能按钮的图标铺满整个按钮，蓝耗圆点悬浮在图标上；冷却时显示顺时针扇形遮罩和剩余秒数。
- **技能 Tooltip**：鼠标悬停技能按钮时显示技能名、蓝耗、冷却和效果描述。
- **技能图标**：来自 freegameassets.com 的 CC0 奇幻 RPG 图标，已用 ImageMagick 统一缩小为 64×64，路径配置在 `heroes.ron` 的 `icon` 字段。

## 代码结构

```
src/
├── main.rs                 # App 组装、GameState、窗口与资源
├── core/
│   ├── rng.rs              # 确定性 RNG（装备与战斗随机）
│   └── stats.rs            # 属性结构、百分比结算、减伤/暴击/治疗公式
├── data/
│   ├── color.rs            # RON 可序列化颜色
│   ├── loader.rs           # 启动时读取并校验 assets/data/*.ron
│   ├── heroes.rs           # 角色/技能运行时结构
│   ├── enemies.rs          # 敌人与波次运行时结构
│   └── equipment.rs        # 装备部位/品级/词条池/随机生成与配置结构
├── combat/
│   ├── components.rs       # ECS 组件、消息、阶段进度资源
│   ├── setup.rs            # 场景、队伍、波次生成
│   ├── animation.rs        # 角色 glTF 动画图与 idle/run/attack/casting 状态机
│   ├── actions.rs          # 自动攻击、技能选择、Buff、法力回复、属性重算
│   ├── damage.rs           # 伤害/治疗/Buff 结算、死亡、失败判定
│   ├── flow.rs             # 波次推进、镜头跟随、通关奖励、重开
│   └── effects.rs          # 世界坐标投影到屏幕的浮动战斗信息
├── progression/
│   └── mod.rs              # 等级曲线、经验结算、药水库存
└── ui/
    ├── cooldown.rs         # 技能冷却 UI 材质
    ├── hud.rs              # 底部队伍栏、Boss 血条、技能冷却与 Tooltip
    ├── stats_panel.rs      # 三个战斗统计面板
    ├── overlay.rs          # 胜利/失败结算
    └── theme.rs            # 字体、配色、通用文本 Bundle
```

## 设计上的约定

- 角色/敌人/技能/装备的平衡数值集中在 `assets/data/*.ron`，代码中的 Rust 结构只负责反序列化与运行时逻辑。
- 技能与角色是数据驱动的：新增角色主要是在 `heroes.ron` 增加定义，战斗层通过 `SkillEffect` 解释执行。
- 公式类常量（减伤 `K`、等级成长、基础攻击间隔等）仍在 `core/stats.rs` 中，属于规则而不是配置。
- 装备词条内部以小数存储（`0.05` 表示 5%），避免显示与计算之间的转换错误。
- 中文 UI 依赖 Bevy 的 `system_font_discovery`，会优先使用系统里的微软雅黑/Noto Sans CJK；后续如果要跨平台稳定表现，建议随包内置一份中文字体。
- 当前为了方便原型验证，战斗是全自动的；手动控制、暂停和技能选择尚未接入。
- 技能冷却遮罩使用自定义 UI 材质着色器（`assets/shaders/skill_cooldown.wesl`），避免为每一帧预烘焙贴图。
